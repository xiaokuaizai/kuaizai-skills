# 支线输入预处理

当 SU 表或 SEG prompt 不在 parser 默认识别范围时，**不改 skill 脚本**，在支线自己工作区里做预处理（生成新的 SU 表 / prompt 副本），让 skill 走标准流程。

## 06 支线（露营周末）实例

### SU 表：8 列平铺主表 + `### SU-XX 拆分` 4 列子表（混合式）

**特征**：
- 主表 8 列：`| SU ID | 场景 | 类型 | 说话人 | 原始文本 | 估算时长 | 是否拆分 | 拆分方案 / 备注 |`
- 拆分片段定义在表尾 `### SU-XX 拆分` 子表（4 列：片段 / 原文 / 估算时长 / 拆分理由）
- 子片段 ID 是大写连字符形式（SU-01-A），parser 只认小写无连字符（SU-01a）
- "估算时长"列带 `s` 后缀（9.5s），17 支线嵌套式 parser 的正则 `[\d.]+` 不匹配

**预处理**（在工作区生成 `SU表_预处理.md`，不动原文件）：
1. 把 `### SU-XX 拆分` 子表转成 17 支线嵌套式 `- **SU-XXa**：\`text\`` 列表
2. 主表父行的"拆分方案"列加 `→ SU-XXa / SU-XXb / ...` 引用
3. 估算时长 `9.5s` → `9.5`（去 `s` 后缀）

参考脚本：`06_露营周末/minimax-story-双语字幕/convert_su_table.py`

### SEG prompt：时间轴 + 台词分离格式（`.txt` 后缀）

**特征**：
- 路径在 `00_元数据/提示词/SEG-XX_prompt.txt`（不是 `doc/minimax_h3_prompts/SEG-XX_prompt.md`）
- 时间轴段和台词段分离，台词用 `- 旁白：text` / `- 江彻：text`，**没有引号包裹**
- 时间码格式 `00:00.00-00:04.00:`（点号分隔，不是 `–`）
- **一行可能塞多个说话人**（格式混乱）：
  ```
  - 旁白：A small fountain... evening light. 江彻：Although there were...
  ```

**预处理**（生成到 `故事板/doc/minimax_h3_prompts/SEG-XX_prompt.md`，让 parser 走默认 `--format shot`）：
1. 解析时间轴段（N 个 shot）和台词段（M 句）
2. 按 SEG 内顺序对齐：台词数 == shot 数 → 一一对应；< shot 数 → 前面分配、后面留白；> shot 数 → 按比例分
3. **识别一行多说话人**：用正则 `(?<=[.!?。！？])\s*([一-龥]{2,4})：` 在 `. ! ? 。 ！ ？` 后查找下一个说话人标记并拆分
4. 输出成 04 支线的单行格式：`- 0:00.0–0:04.0（SH-001）：描述 旁白（Luna）："text"`

**角色映射**：支线 6 用"安奇"非"安琪"，"对白："（无明确说话人）按 SU 表归属处理

**注意**：parser 的 `DEFAULT_SPEAKER_MAP` 不含"安奇"，跑 `01_extract_seg_lines.py` 时**必须**传 `--speaker-map-json`（含"安奇"→ An Qi 映射），否则所有"安奇"说话的 shot 都识别失败（06 支线因此丢了 24 个 shot）。

参考脚本：`06_露营周末/minimax-story-双语字幕/convert_prompts.py`

### 一行多句无句号分隔（SEG-13 实例）

prompt 行：`- 对白：We need to strengthen teamwork I agree`——SU-30 和 SU-31 之间**没有句号**，正则 `(?<=[.!?。！？])\s*([一-龥]{2,4})：` 抓不到拆分点。

**修复**：预处理时手工在 prompt 里拆成 2 个相邻 shot，让 parser 生成 2 个 shot 对应 2 个 SU：

```
- 0:4.5–0:6.0（SH-003）：... 安奇（Dacey）："We need to strengthen teamwork"
- 0:6.0–0:7.0（SH-004）：... 江彻（Lucas）："I agree"
```

参考文件：`06_露营周末/故事板/doc/minimax_h3_prompts/SEG-13_prompt.md`

### 翻译后处理：角色名错误统一

Kimi 翻译时可能引入角色名错误（"江澈"/"蒋澈"/"安奇"），需统一修正为项目标准（"江彻"/"安琪"）。在 `su_zh.json` 上做后处理：

```python
for k, v in su_zh.items():
    v = v.replace('江澈', '江彻').replace('蒋澈', '江彻').replace('安奇', '安琪')
```

## 通用判断流程

接到新支线时按以下顺序检查：

1. **SU 表格式**：是 8 列平铺、10 列平铺、17 嵌套式、还是混合式？
   - 用 `parse_su_table` 实测，看输出 SU 数和 fragments 数是否符合预期
   - 拆分片段没识别 → 转 17 嵌套式

2. **SEG prompt 格式**：`doc/minimax_h3_prompts/` 存在？`最终提示词/`？还是 `.txt`？
   - 用 `parse_seg_prompt_shot` 实测，看输出 unit 数是否符合预期
   - 时间台词分离 / 一行多说话人 → 预处理成 04 单行格式

3. **角色名一致性**：项目用"江彻/安琪"，但 prompt 可能写"江澈/安奇"
   - **跑 `01_extract_seg_lines.py` 时传 `--speaker-map-json`**（含"安奇"→ An Qi 映射）
   - 翻译后统一后处理（`su_zh.json` 里 `replace('江澈', '江彻')` 等）

4. **跑 01_extract_seg_lines.py 后看 WARN**：
   - `INCOMPLETE` 数 → SU ↔ shot 对齐问题
   - `未分配 shot` 数 → prompt 解析问题
