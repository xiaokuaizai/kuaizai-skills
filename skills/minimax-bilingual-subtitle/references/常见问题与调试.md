# 常见问题与调试

## 视觉重排（新流程的已知限制）

**症状**：步骤 1 输出多条 `[WARN] 第 N 行英文文本不一致`，配对的 su_id 和 text_zh 错位。

**根因**：minimax-storyboard 在生成 SEG 时，为配合视觉叙事可能调整台词的视觉顺序
（例：SP-12 厨房角落描述在视频里出现在 SP-10 对白之前）。
新流程默认 seg_lines 顺序 == SU 拆分片段顺序，一旦视觉重排就错位。

**当前处理**：
- 步骤 1 会输出前 5 条不一致警告 + 总数
- 仍会按顺序配对（结果可能错位）

**手工修复**：编辑 `seg_lines.json`，把错位的行的 `su_id` / `parent_su` / `text_zh` / `scene` 改成正确的，然后重跑步骤 3-5。

**后续改进**：如果发现视觉重排常见，可以在步骤 1 加 `--match-mode fuzzy`，用 difflib 滑窗匹配 SU 拆分片段。

## 06 支线新发现问题（已修复）

### 问题 1：SEG prompt 一行塞多个说话人

**症状**：某句台词在字幕里丢失，或两句被合并成一句。例：
- SU-53b（"A small fountain..."）丢失，且 SU-53a 被切成两段
- SU-23b / SU-32b 也有类似情况

**根因**：06 支线部分 SEG prompt 的台词段格式混乱，一行塞了 2 个说话人：
```
- 旁白：A small fountain... evening light. 江彻：Although there were...
```
转换脚本原本用 `re.match(r'^- ([^：:]+)：(.+)$', line)` 整行匹配，把"江彻：Although..."也当作旁白文本的一部分，导致该 shot 的台词合并错乱。

**修复**：识别一行多说话人，用 `(?<=[.!?。！？])\s*([一-龥]{2,4})：` 在句号后查找下一个说话人标记并拆分。涉及 SEG：11、14、24。

**预防**：遇到新支线时，先扫描所有 SEG prompt 的台词行是否含多个"名字："标记：
```python
speakers = re.findall(r'(?:^|(?<=[.!?。！？\s]))([一-龥]{2,4})：', line)
if len(speakers) > 1:
    print(f'{f}: {len(speakers)} 个说话人')
```

### 问题 2：角色名不一致（安奇 vs 安琪 / 江澈）

**症状**：
- Kimi 翻译的 `su_zh.json` 里出现"江澈""蒋澈""安奇"等错误角色名。
- **更严重的**：SEG prompt 用"安奇"（非"安琪"），parser 的 `DEFAULT_SPEAKER_MAP` 只认"安琪"，**所有"安奇"说话的 shot 都识别失败**。06 支线因此丢了 24 个 shot（62 → 86）。

**根因**：支线 6 prompt 用"安奇"（非"安琪"），SU 表说话人列是英文（Jiang Che / An Qi），Kimi 翻译时自行脑补中文名，可能写错。

**修复**：
1. **seg_lines 提取**：跑 `01_extract_seg_lines.py` 时传 `--speaker-map-json`，把"安奇"映射到 An Qi：
   ```json
   {
     "旁白": ["Narrator", "旁白", "narration"],
     "安琪": ["An Qi", "安琪", "dialogue"],
     "安奇": ["An Qi", "安琪", "dialogue"],
     "江彻": ["Jiang Che", "江彻", "dialogue"],
     "对白": ["An Qi", "安琪", "dialogue"]
   }
   ```
2. **中文翻译**：翻译完成后统一替换：
   ```python
   v = v.replace('江澈', '江彻').replace('蒋澈', '江彻').replace('安奇', '安琪')
   ```

**诊断方法**：跑完步骤 1 后看输出 `共解析 N 个 shot`——如果远少于 SU 表台词行数，多半是"安奇"没识别。

**注意**：项目标准角色名是"江彻 / 安琪"。处理新支线时，**先确认 prompt 里用什么中文名**（安琪/安奇/江澈/蒋澈 都是变体），用 `--speaker-map-json` 加映射，不要改 parser 脚本。

### 问题 3：SU 表混合式（8 列 + ### SU-XX 拆分 子表）

**症状**：`parse_su_table` 返回 0 个 SU，或所有 SU 都是 1 个 fragment（拆分片段丢失）。

**根因**：06 支线 SU 表是混合式（详见 `references/输入要求.md`），parser 只认 17 嵌套式 / 03 平铺 10 列 / 04 平铺 8 列。

**修复**：在工作区里预处理后跑（详见 `references/支线输入预处理.md`）。

### 问题 4：prompt 一行塞多句无句号分隔（"teamwork I agree"）

**症状**：SU-30 "We need to strengthen teamwork" 和 SU-31 "I agree" 在字幕中合并成 1 条，或后者丢失。

**根因**：06 支线 SEG-13 prompt 台词行是 `- 对白：We need to strengthen teamwork I agree`——两句之间**没有句号**，convert_prompts.py 的正则 `(?<=[.!?。！？])\s*([一-龥]{2,4})：` 抓不到拆分点。

**修复**：预处理时识别这种"一行多句无句号"的 case，手工在 prompt 里给 SU-30 / SU-31 各拆一个虚拟 shot（时间重叠或相邻），让 parser 生成 2 个 shot 对应 2 个 SU。详见 `06_露营周末/故事板/doc/minimax_h3_prompts/SEG-13_prompt.md`：
```
- 0:4.5–0:6.0（SH-003）：... 安奇（Dacey）："We need to strengthen teamwork"
- 0:6.0–0:7.0（SH-004）：... 江彻（Lucas）："I agree"
```

**诊断方法**：跑完步骤 1 后对比 seg_lines.json 行数 vs SU 表台词行数。如果 SU 表有 N 句但 seg_lines 只有 M < N 行，检查是不是 prompt 一行塞了多句没拆。

### 验证指标（步骤 3 输出）

跑完 `03_align_by_order.py` 后看这几个数字：
- `whisper 校正 N / 理论时间 M`：N 越大越好（N == 总 shot 数最佳）
- 时长 < 0.5s 的字幕数：应该接近 0
- theory 时间的字幕数：应该接近 0

可用以下脚本快速诊断：
```python
sp = json.loads(Path('subtitle_split.json').read_text(encoding='utf-8'))
short = [s for s in sp if s['actual_end'] - s['actual_start'] < 0.5]
theory = [s for s in sp if s['align_source'] == 'theory']
overlap = [(a,b) for i,a in enumerate(sp) for b in sp[i+1:]
           if a['actual_start'] < b['actual_end'] and b['actual_start'] < a['actual_end']
           and min(a['actual_end'], b['actual_end']) - max(a['actual_start'], b['actual_start']) > 0.5]
print(f'超短: {len(short)}, theory: {len(theory)}, 重叠: {len(overlap)}')
```

另外，跑完后**抽样验证**关键台词是否在字幕中：
```python
# 检查某句台词是否丢失
keyword = 'A small fountain'
found = [s for s in sp if keyword.lower() in s['text_en'].lower()]
print(f'找到 {len(found)} 条含 "{keyword}" 的字幕')
```

## 04 支线新发现问题（已修复）

### 问题 1：同时间多 shot（同帧多说话人）

**症状**：某 shot 字幕时长只有 0.1s（如 7:26 Jiang Che 台词），或者字幕时间完全重叠。

**根因**：minimax-storyboard 的 prompt 常把两人对话写在同一时间（如 `0:04.0–0:09.0` 江彻+安琪各一句）。whisper 段对每个 shot 是 1 对 1 分配，导致某些 shot 拿不到时间。

**修复**：`03_align_by_order.py` 的 `align_seg_shots()` 已支持同时间 shot 分组，whisper 段在组内按顺序轮流分配。

### 问题 2：1 个 whisper 段跨越多个 shot

**症状**：SU 表把 "A little, but I will not weep." 拆成 2 个 shot（SP-70, SP-71），但 whisper 识别成 1 段。第一个 shot 拿到 0.1s，第二个 shot 回退 theory。

**修复**：whisper 段按**时间重叠占比**切分到不同的 shot 组。每个 shot 分到的片段用 `synthetic: True` 标记。

### 问题 3：SU 表拆分建议列是文字描述（非 frag_id）

**症状**：04 支线的 SU 表（8 列）"拆分建议"列写的是 `拆分点 A：after "loud."`，不是子片段 ID 列表。导致 `parse_su_table` 解析时找不到子片段，走 fallback 整段作 1 个 fragment。

**影响**：长字幕不会被预拆，需要 `force_split_subtitle` 兜底强拆。结果 ASS 字幕可能比你预期的更碎。

**处理**：暂不影响正确性，只是字幕粒度比 03 更细。

### 验证指标（步骤 3 输出）

跑完 `03_align_by_order.py` 后看这几个数字：
- `whisper 校正 N / 理论时间 M`：N 越大越好（N == 总 shot 数最佳）
- 时长 < 0.5s 的字幕数：应该接近 0
- theory 时间的字幕数：应该接近 0

可用以下脚本快速诊断：
```python
sp = json.loads(Path('subtitle_split.json').read_text(encoding='utf-8'))
```

## BUG 修复历史（旧流程遗留，供参考）

### BUG 5：SU 顺序贪心匹配失步（视觉重排）

**症状**：83 个 SU 只匹配上 43 个，后续 SU 时间戳全部错位。

**根因**：`03_align_su.py` greedy 模式的 `ti` 指针只会前进，不允许回头匹配。

**修复**：旧版加了 fuzzy 模式（difflib 滑窗 + 视觉重排）。**新版完全放弃文本匹配，不再有此 bug**。

### BUG 1：SU 跨 SEG 匹配错乱

**症状**：SU-44 时间戳 12s（实际应为 6s），matched_units 包含上一个 SU 的尾巴。

**根因**：贪心匹配条件 `accumulated in frag_norm` 在 accumulated 是 frag 的**严格前缀**时误触发 break。

**修复**：只在 `frag_norm in accumulated`（frag 完整出现）时 break。**新版不做跨 SEG 文本匹配，不再有此 bug**。

### BUG 2：normalize 误去引号

**症状**：SU-01 fragment 2 (`with the words "Sports Club..." written beside it.`) 始终匹配失败。

**根因**：`normalize` 里的 `s.strip('"')` 把 unit 末尾的合法闭引号去掉了，导致后续拼接 accumulated 里 challenge 后无闭引号，而 frag_norm 里有闭引号，匹配永远失败。

**修复**：normalize 不再去引号。**新版不做文本匹配，不再有此 bug**。

### BUG 6：split_subtitles 兜底拆分未实现

**症状**：38 条字幕超出 20 词 / 30 字 / 10s 限制，但步骤 6 输出 `保留整段 N`，并未真正拆分。

**修复**：新增 `force_split_subtitle()` 递归强制拆。新版保留此逻辑在 `lib/subtitle_splitter.py`。

### BUG 7：中英混排硬切切断英文单词

**症状**：SU-01b 中文 `路口的信箱mailbox上贴着物业通知。` 被切成 `路口的信箱mailb` + `ox上贴着物业通知。`。

**修复**：`find_safe_cut_zh()` 避开 ASCII 字母边界。新版保留此逻辑。

### BUG 8/9/10：SP 命名 / 动作描述 / SEG 格式

已修复：
- SP-XX 命名兼容（`parse_su_table` 正则同时识别 SU/SP）
- 动作描述剥离（`extract_spoken` 只保留引号内台词）
- 两种 SEG prompt 格式（shot / seg）

## 调试技巧

### 检查 seg_lines 配对质量

打开 `seg_lines.json`，看每行的：
- `su_id` 是否合理（连续递增）
- `text_zh` 是否对应 `text_en` 的中文翻译
- 步骤 1 输出的"英文不一致"警告数

### 检查 SEG 时长是否准确

```bash
ffprobe -v error -show_entries format=duration \
  -of default=noprint_wrappers=1:nokey=1 \
  "SEG-XX/SEG-XX.mp4"
```

若 Σ实测 - Σ标称 > 5s，必须用实测。

### 检查 whisper 识别质量

打开 `whisper_by_seg.json`，看 `avg_logprob`：
- `> -0.3`：识别很确定
- `-0.3 ~ -0.7`：可能有小错
- `< -0.7`：很可能错了

### 烧录后字幕不见了？

可能原因：
1. ASS 时钟错位 → ffmpeg 加 `-copyts`
2. ASS 路径问题 → Windows 下用相对路径，cd 到 ASS 所在目录
3. 编码问题 → ASS 用 utf-8-sig（带 BOM）保存
4. 字体缺失 → 检查 `C:\Windows\Fonts\simfang.ttf` 是否存在

## 调优参数

### whisper VAD 参数（步骤 2）

```python
vad_parameters = dict(
    threshold=0.35,              # 灵敏度（0.2~0.5，越小越灵敏）
    min_silence_duration_ms=300, # 静音 ≥300ms 切分
    speech_pad_ms=200,           # 语音前后各延 200ms
)
```

若 whisper 漏识别（短句被吃掉）：降低 threshold 到 0.25。
若 whisper 误识别（静音被当语音）：提高 threshold 到 0.45。

### 拆分阈值（步骤 3）

默认：英文 ≤20 词 / 中文 ≤30 字 / 时长 ≤10s。

Netflix 惯例：每行 ≤42 字符 / ≤2 行。
YouTube 惯例：每行 ≤40 字符 / ≤2 行。

中文一行建议 ≤15-20 字（过多显示不全）。
