# 时间戳对齐算法（新 6 步流程）

## 核心思想

**不做跨 SEG 文本匹配**。SEG 内的行与 whisper 段按"时间重叠最大"配对。

```
seg_lines.json          N 行（SEG 内语音行，含中英配对）
        ↓ whisper 按 SEG 识别
whisper_by_seg.json     每 SEG 的精确语音段
        ↓ 时间重叠最大配对
subtitle_split.json     N 条字幕（actual 时间戳）
```

## 时间戳的两层概念

每行 seg_line 有 4 个时间字段：

| 字段 | 含义 | 来源 |
|---|---|---|
| `seg_start` / `seg_end` | SEG 内相对时间（0 ~ 8-14s） | SEG prompt 时间轴 |
| `abs_start` / `abs_end` | 视频绝对时间（理论值） | seg_start + Σ前面所有 SEG 的实测时长 |
| `actual_start` / `actual_end` | 视频绝对时间（whisper 校正值） | 步骤 3 输出 |

**关键坑**：Minimax H3 实际 SEG 时长 ≠ 标称时长。**必须用 ffprobe 实测每 SEG 时长**，然后累加计算 abs_start。

## 对齐算法（步骤 3）

### 为什么用"时间重叠最大"而不是文本匹配

| 方案 | 优点 | 缺点 |
|---|---|---|
| 文本匹配（旧） | 不依赖时间精度 | normalize/引号/前缀 bug、视觉重排问题 |
| 时间重叠最大（新） | 不需要文本匹配、无 normalize bug | 依赖 SEG 内时间戳精度 |

**SEG 内时间戳精度足够**：whisper 按 SEG 识别（8-14s 短视频），时间戳漂移 < 0.3s，而 SEG 内行理论时间与实际时间重叠度通常 > 70%。

### 算法

```
输入：seg_lines（按 SEG 分组）+ whisper_by_seg
对每 SEG：
  1. 行按 seg_start 排序，whisper 段按 rel_start 排序
  2. 按 (seg_start, seg_end) 完全相同的行分到一组（同帧多说话人）
  3. 对每个 whisper 段 w：
     a. 计算 w 对每组的 overlap
     b. 若 w 只覆盖 1 组 → 整段分配给该组
     c. 若 w 跨越多个组 → 按时间重叠占比切分 w，每组分一段（synthetic=True）
  4. 组内分配：
     - whisper 段数 == 组内行数 → 一一对应轮流分配
     - whisper 段数 < 组内行数 → 按行顺序均分 whisper 段时间
     - whisper 段数 > 组内行数 → 相邻合并，多余段给最后一行
  5. 行 l 的 actual_start = seg_offset + min(assigned.rel_start)
     行 l 的 actual_end   = seg_offset + max(assigned.rel_end)
     若 l 没有分配到任何 w → 用理论时间 [abs_start, abs_end]
跨 SEG 校正：
  行 i 的 actual_end ≤ 行 i+1 的 actual_start - gap（默认 0.05s）
```

### 边界情况

| 情况 | 处理 |
|---|---|
| 一行很短（<0.5s），whisper 没单独识别 | 该行没分配到 w，回退理论时间 |
| whisper 段跨多行 | 按时间重叠占比切分到多行 |
| 同时间多行（同帧多说话人） | 分到一组，whisper 段在组内轮流分配 |
| 1 个 whisper 段含多句（被 SU 表拆成多行） | 按行顺序均分 whisper 段时间 |
| 某 SEG 完全没有 whisper 段 | 所有行用理论时间 |
| whisper 段与所有行都不重叠 | 忽略（可能是识别错误） |

## 长字幕拆分（步骤 3 内置）

seg_lines 是 SU 拆分片段级别，按 SU 表拆分应已满足长度限制。仍兜底：

- 英文 > 20 词 / 中文 > 30 字 / 时长 > 10s → 强制拆
- 优先级：英文句末标点 → 词数硬切 → 中文标点 → 中文硬切（避 ASCII 词）

## 已知限制

**视觉重排**：如果 minimax-storyboard 视觉重排（SU 顺序 ≠ SEG 顺序），按顺序配对的 su_id 和 text_zh 会错位。步骤 1 会输出英文一致性警告（前 5 条 + 总数），发现后需手工调整 seg_lines 顺序或改用其他方案。

## 旧版算法（已废弃）

旧版用三层文本匹配（timeline unit ↔ SU ↔ zh_units），normalize + 包含判断 + 前缀 break 引发一系列 bug：

- SU-44 跨 SEG 匹配错成 12s（前缀 break bug）
- normalize 误去引号导致后续拼接失败
- 视觉重排时 greedy 失步

新方案完全放弃文本匹配，只按时间重叠配对，避免这一类问题。
