# 分批生成策略

> 本文件规定 `/minimax-video-dispatch` 如何分批次提交视频生成任务，确保用户在正式全量生成前有机会检查质量。

## 核心原则

1. **小步快跑**：第一批只做少量 SEG，验证平台、参数、prompt、参考图是否正常。
2. **用户确认才继续**：每一批完成后必须暂停，等用户查看并确认无问题。
3. **不可静默跳过**：任何失败 SEG 必须记录并向用户汇报，禁止自动跳过。
4. **费用可控**：每一批提交前都要给出预估费用。

## 批次划分

假设总共有 N 个 SEG 需要生成：

| 批次 | 数量 | 触发条件 |
|---|---|---|
| 第一批（试跑） | `min(4, N)` | 必须先生成 |
| 第二批（验证） | `min(10, N - 已生成)` | 第一批确认无问题后 |
| 后续批次 | 用户决定 | 第二批确认无问题后 |

## 具体流程

```text
开始
  │
  ▼
计算总 SEG 数 N
  │
  ▼
第一批：取 SEG[0:4]，提交生成
  │
  ▼
轮询全部任务到终态（succeeded / failed / cancelled）
  │
  ▼
下载成功产物，整理失败原因
  │
  ▼
向用户汇报：成功列表、失败列表、本地路径、费用
  │
  ▼
等待用户确认
  │   └── 有问题 → 停止，修复 prompt/参考图后重新从第一批开始
  │
  ▼
第二批：取 SEG[4:14]，提交生成
  │
  ▼
轮询、下载、汇报、等待确认
  │
  ▼
询问用户：
  - 全量生成剩余 SEG
  - 继续分批生成（询问数量）
  - 停止
```

## 批次选择规则

1. 按导演总表中的 SEG 顺序生成，不跳跃。
2. 如果某个 SEG 失败，该 SEG 在后续批次中重新提交，不跳过。
3. 用户可以在任意批次后要求停止；已生成产物保留，未生成 SEG 记录到 `video_generation_log.json`。

## 费用预估

每一批提交前，按以下公式估算：

```text
预估费用 = Σ(每个 SEG 的 duration × 单秒价格)
         + 参考图超出 5 张部分 × 单张价格
         + 参考视频输入秒数 × 对应分辨率单秒价格
         + H3-Context-IR 调用次数 × 单次价格
```

具体单价见 `references/平台配置与价格.md`。

## 用户交互话术模板

### 第一批前

```text
本次共 N 个 SEG，将分批次生成。
第一批生成前 4 个 SEG：SEG-01、SEG-02、SEG-03、SEG-04。
预计费用：XX 元 / $XX。
确认提交吗？
```

### 第一批完成后

```text
第一批已完成：
- 成功：SEG-01、SEG-02
- 失败：SEG-03（原因：...）、SEG-04（原因：...）
- 本地产物路径：...
- 实际费用：XX 元 / $XX

请查看后确认是否继续第二批（SEG-05 ~ SEG-14）。
```

### 第二批完成后

```text
第二批已完成：...

剩余 SEG 数量：X。
请选择：
1. 全量生成剩余全部 SEG。
2. 继续分批生成，指定数量。
3. 停止生成。
```

## 重试规则

单个 SEG 生成失败时：

1. 第一次失败：记录错误信息，保持 prompt 不变，自动重试 1 次。
2. 第二次失败：暂停该 SEG，向用户汇报，等待用户决定是否修改 prompt 后重试。
3. 同一 SEG 最多重试 2 次；若仍失败，必须人工介入。

## 日志记录

每批完成后更新 `00_元数据/清单/video_generation_log.json`，字段包括：

- `batch_index`：批次序号
- `segment_ids`：本批次 SEG 列表
- `platform`：使用的平台
- `resolution`：分辨率
- `ratio`：比例
- `mode`：生成模式
- `tasks`：每个 SEG 的 task_id、状态、产物 URL、本地路径、费用
- `submitted_at`：提交时间
- `completed_at`：完成时间
