# 错误处理与重试

> 本文件说明调用 Minimax 视频生成接口时可能遇到的错误码、处理方式和重试策略。

## 状态码与含义

| HTTP 状态码 | 错误类型 | 含义 | 处理方式 |
|---|---|---|---|
| 200 | 成功 | 创建任务成功，返回 task_id | 正常流程 |
| 400 | bad_request_error | 参数错误，如缺少 text | 检查 prompt 和参数，修正后重试 |
| 401 | authorized_error | API key 无效或未传 | 检查 .env 中的 key，不自动重试，**禁止私自切换到其他 key** |
| 402 | insufficient_balance_error | 余额/额度不足 | 停止生成，通知用户充值 |
| 422 | unprocessable_entity_error | 内容涉及敏感内容 | 修改 prompt，避免敏感词后重试 |
| 429 | rate_limit_error | 触发限流 | 等待 30 秒后重试，最多 3 次；秘塔中转站还需检查是否超过单个 key 并发上限 4。**严禁自动切换到其他 key，必须暂停并询问用户。** |
| 500 | server_error | 服务端内部错误 | 等待 60 秒后重试，最多 3 次 |

## 任务状态

查询任务时可能返回的状态：

| 状态 | 含义 | 处理方式 |
|---|---|---|
| queued | 排队中 | 继续轮询 |
| running | 运行中 | 继续轮询 |
| succeeded | 成功 | 下载产物 |
| failed | 失败 | 记录原因，按重试规则处理 |
| cancelled | 已取消 | 跳过，不重复提交 |

## 轮询策略

```python
# 初始等待 10 秒，之后每 10 秒查询一次，最多 30 分钟
poll_interval = 10      # 轮询间隔（秒）
max_poll_time = 1800    # 最大轮询时间（秒）
```

如果任务长时间处于 `queued` 或 `running`，继续轮询直到超时。超时后标记为 `timeout` 并向用户汇报。

## 重试规则

### 创建任务阶段

| 错误码 | 是否重试 | 重试次数 | 间隔 |
|---|---|---|---|
| 400 | 否 | - | 修正参数后重新提交 |
| 401 | 否 | - | 检查 key |
| 402 | 否 | - | 停止，通知用户 |
| 422 | 否 | - | 修改 prompt 后重新提交 |
| 429 | 是 | 3 | 30 秒 |
| 500 | 是 | 3 | 60 秒 |

### 单个 SEG 失败后的处理

1. 第一次失败：自动重试 1 次，保持原 prompt 和参数不变。
2. 第二次失败：暂停该 SEG，记录到失败列表，等待用户决定是否修改后重试。
3. 同一 SEG 最多重试 2 次（含自动重试）。

### 下载失败后的处理

1. 先重新查询任务，获取新的下载链接。
2. 重新下载，最多重试 3 次。
3. 仍失败则标记为 `download_failed`，记录到日志。

## 错误记录格式

```json
{
  "segment_id": "SEG-01",
  "task_id": "424010985738629",
  "error_at": "create|query|download",
  "http_code": 422,
  "error_type": "unprocessable_entity_error",
  "message": "video description contains sensitive content (1026)",
  "request_id": "021785229015510a2c883cf675b9804d",
  "retry_count": 1,
  "status": "pending_user_decision"
}
```

## 用户通知模板

### 余额不足

```text
平台返回 402 余额不足，已停止生成。
请充值后再继续。当前已生成 SEG：...，未生成 SEG：...
```

### 敏感内容

```text
SEG-01 提交失败（422）：提示词涉及敏感内容。
错误信息：...
请修改 prompt 后告诉我是否重试。
```

### 限流

```text
平台触发限流（429），将在 30 秒后自动重试。
已重试 X / 3 次。
```
