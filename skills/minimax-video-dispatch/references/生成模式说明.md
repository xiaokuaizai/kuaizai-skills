# 生成模式说明

> 本文件说明 `/minimax-video-dispatch` 支持的所有生成模式。
> Minimax 官方与秘塔中转站的接口参数完全一致，只有 Base URL 和 API key 不同。
> 原始官方文档见 `references/official-docs/` 目录。

---

## 通用请求字段说明

所有视频生成接口共用以下基础字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` | string | 是 | 固定为 `MiniMax-H3` |
| `content` | array | 是 | 多模态输入数组，必须包含至少一个非空 `text` 项 |
| `resolution` | string | 是 | 输出分辨率：`768P` / `2K` |
| `duration` | integer | 是 | 输出时长：4–15 秒整数 |
| `ratio` | string | 视模式而定 | 宽高比，见各模式说明 |
| `callback_url` | string | 否 | 任务状态变更回调地址 |
| `aigc_watermark` | boolean | 否 | 是否添加 AIGC 水印，默认 `false` |

### content 数组元素通用结构

```python
{
    "type": "text",        # text / image_url / video_url / audio_url
    "text": "...",         # type=text 时必填
    "image_url": {"url": "..."},   # type=image_url 时必填
    "video_url": {"url": "..."},   # type=video_url 时必填
    "audio_url": {"url": "..."},   # type=audio_url 时必填
    "role": "reference_image"      # 用途，部分类型必填
}
```

### role 取值说明

| role | 适用 type | 说明 |
|---|---|---|
| `first_frame` | `image_url` | 首帧图片（图生视频） |
| `last_frame` | `image_url` | 尾帧图片（图生视频-首尾帧） |
| `reference_image` | `image_url` | 参考图片（多模态参考生视频） |
| `reference_video` | `video_url` | 参考视频（多模态参考生视频） |
| `reference_audio` | `audio_url` | 参考音频（多模态参考生视频） |
| `base_video` | `video_url` | 源视频（视频再生成） |

### 素材硬限制

| 素材类型 | 数量限制 | 时长/大小限制 |
|---|---|---|
| 首帧图 | ≤ 1 | ≤ 30 MB，宽高 256–5760 px，宽高比 0.4–2.5 |
| 尾帧图 | ≤ 1 | 同上 |
| 参考图 | ≤ 9 | 同上 |
| 参考视频 | ≤ 3 | 单段 2–15 秒，总时长 ≤ 15 秒，≤ 50 MB |
| 参考音频 | ≤ 3 | 单段 2–15 秒，总时长 ≤ 15 秒，≤ 15 MB |
| 请求体总大小 | - | ≤ 64 MB，大文件必须使用公网 URL |

### 重要互斥规则

只要 `content` 中出现 `reference_image` / `reference_video` / `reference_audio` 任一 role，**就不能再出现** `first_frame` / `last_frame`，反之亦然。

---

## 模式总览

| 模式 | 接口 | 说明 | 典型使用场景 |
|---|---|---|---|
| t2va | `POST /v2/video_generation` | 文生视频 | 只有文本 prompt |
| i2va | `POST /v2/video_generation` | 图生视频 | 提供首帧或首尾帧图片 |
| r2va | `POST /v2/video_generation` | 多模态参考生视频 | 文本 + 参考图/视频/音频 |
| regeneration_by_task | `POST /v2/video_regeneration` | 按任务 ID 再生成 | 把已有 768P 任务升级成 2K |
| regeneration_by_video | `POST /v2/video_regeneration` | 按源视频再生成 | 传入 base_video 和原始输入升级 2K |
| h3_context_ir | `POST /v2/h3_context_ir` | 提示词增强 | 返回结构化增强 prompt，不生成视频 |

---

## t2va：文生视频

### 调用示例

```python
import requests

response = requests.post(
    "https://api.minimaxi.com/v2/video_generation",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "MiniMax-H3",
        "content": [
            {"type": "text", "text": "一个男孩在海边打篮球"}
        ],
        "resolution": "2K",
        "duration": 5,
        "ratio": "9:16"
    },
)
```

### 特殊说明

- `ratio` **必填**，且不能为 `adaptive`。
- 可用 `ratio`：`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`。

---

## i2va：图生视频

### 首帧模式调用示例

```python
import requests

response = requests.post(
    "https://api.minimaxi.com/v2/video_generation",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "MiniMax-H3",
        "content": [
            {"type": "text", "text": "..."},
            {
                "type": "image_url",
                "image_url": {"url": "https://xxx/first.jpg"},
                "role": "first_frame"
            }
        ],
        "resolution": "2K",
        "duration": 5,
        "ratio": "adaptive"
    },
)
```

### 首尾帧模式调用示例

```python
json = {
    "model": "MiniMax-H3",
    "content": [
        {"type": "text", "text": "..."},
        {"type": "image_url", "image_url": {"url": "..."}, "role": "first_frame"},
        {"type": "image_url", "image_url": {"url": "..."}, "role": "last_frame"}
    ],
    "resolution": "2K",
    "duration": 5,
    "ratio": "adaptive"
}
```

### 特殊说明

- 单张图不填 `role` 时默认按 `first_frame` 处理。
- `ratio` 会被强制设为 `adaptive`，由输入图片决定实际比例；传入其他值会被忽略。
- 首尾帧需成对出现。

## r2va：多模态参考生视频

### 调用示例

```python
import requests

response = requests.post(
    "https://api.minimaxi.com/v2/video_generation",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": """
Image 1 是核心人物参考，严格保留人物五官、发型、服饰特征；
Image 2 是场景环境参考，继承场景物体与空间结构；
Reference Audio 1 是主要人物说话音色；
Reference Video 1 是人物运动动作参考。

生成视频时长5秒，画面运动流畅。
"""
            },
            {"type": "image_url", "image_url": {"url": "https://xxx/img1.jpg"}, "role": "reference_image"},
            {"type": "image_url", "image_url": {"url": "https://xxx/img2.jpg"}, "role": "reference_image"},
            {"type": "audio_url", "audio_url": {"url": "https://xxx/audio1.mp3"}, "role": "reference_audio"},
            {"type": "video_url", "video_url": {"url": "https://xxx/video1.mp4"}, "role": "reference_video"}
        ],
        "resolution": "2K",
        "duration": 5,
        "ratio": "adaptive"
    },
)
```

### prompt 中素材引用的编号规则

多模态参考生视频的 prompt 必须按 `content` 数组中同类型素材的出现顺序来编号引用：

| 素材类型 | content 中出现顺序 | prompt 引用名 |
|---|---|---|
| reference_image | 第 1 张 | `Image 1` |
| reference_image | 第 2 张 | `Image 2` |
| reference_image | 第 3 张 | `Image 3` |
| reference_image | 第 4 张 | `Image 4` |
| reference_image | 第 5 张 | `Image 5` |
| reference_audio | 第 1 段 | `Reference Audio 1` |
| reference_audio | 第 2 段 | `Reference Audio 2` |
| reference_audio | 第 3 段 | `Reference Audio 3` |
| reference_video | 第 1 段 | `Reference Video 1` |
| reference_video | 第 2 段 | `Reference Video 2` |

#### 关键规则

1. **编号只按同类型素材顺序算**，不按整个 `content` 数组的全局顺序算。
2. **prompt 中的编号必须与 content 顺序严格对应**。
3. **调整 content 顺序时，prompt 必须同步改编号**。
4. 这是提示词工程实践，不是 API 强制校验字段，但内部必须保持一致。

### 特殊说明

- `ratio` 可选，默认 `adaptive`；也可显式指定具体比例。
- 参考音频总时长尽量接近设置的 `duration`，否则声音可能拉伸畸变。
- 多份音频同时传入，模型会混合音色，不是简单拼接。
- 多个 reference_video 同时传入容易动作打架，建议一个负责人物动作、一个负责运镜，并在 text 里明确分工。
- 5 张参考图越多越容易互相污染，优先把最重要的人物图放在最前面（Image 1）。

## regeneration_by_task：按任务 ID 再生成

### 调用示例

```python
import requests

response = requests.post(
    "https://api.minimaxi.com/v2/video_regeneration",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "MiniMax-H3",
        "source_task_id": "424010985738629",
        "resolution": "2K"
    },
)
```

### 特殊说明

- 源任务必须是当前账号的、状态为 `succeeded` 的 `/v2/video_generation` 任务。
- 源任务须在 7 天查询窗口内。
- 该模式需开通白名单。
- 再生成任务不支持 `callback_url` 之外的大部分创建字段。

## regeneration_by_video：按源视频再生成

### 文生源视频再生成示例

```python
import requests

response = requests.post(
    "https://api.minimaxi.com/v2/video_regeneration",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "MiniMax-H3",
        "content": [
            {"type": "text", "text": "..."},
            {
                "type": "video_url",
                "video_url": {"url": "https://xxx/h3-t2va-768p.mp4"},
                "role": "base_video"
            }
        ],
        "resolution": "2K"
    },
)
```

### 多模态源视频再生成示例

```python
json = {
    "model": "MiniMax-H3",
    "content": [
        {"type": "text", "text": "..."},
        {"type": "video_url", "video_url": {"url": "..."}, "role": "reference_video"},
        {"type": "audio_url", "audio_url": {"url": "..."}, "role": "reference_audio"},
        {"type": "video_url", "video_url": {"url": "..."}, "role": "base_video"}
    ],
    "resolution": "2K"
}
```

### 特殊说明

- `content` 中必须且只能有一个 `role=base_video` 的视频项。
- 必须原样提交生成 768P 源视频时的全部输入。
- `text` 必须使用生成 768P 时实际送入模型的最终 prompt，不能用 H3-Context-IR 处理前的原始 prompt。
- `base_video` 必须符合 MiniMax-H3 768P 输出规格：含音轨、24 fps、宽高能被 32 整除、面积在 768×768 到 768×1344 之间、总帧数 107–362 帧。

## h3_context_ir：提示词增强

### 调用示例

```python
import requests

response = requests.post(
    "https://api.minimaxi.com/v2/h3_context_ir",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
    json={
        "model": "MiniMax-H3",
        "content": [
            {"type": "text", "text": "一个男孩在海边打篮球"}
        ],
        "duration": 5,
        "ratio": "9:16"
    },
)
```

### 特殊说明

- 本接口**只返回增强后的 prompt，不创建视频生成任务**。
- 无 `resolution` 字段。
- 成功后从查询接口的 `content.prompt` 获取增强提示词。
- 返回的增强 prompt 可直接用于 `/v2/video_generation` 的 `text`。

## 查询任务状态

所有创建接口都返回 `task_id`，需轮询查询：

```python
import requests

response = requests.get(
    "https://api.minimaxi.com/v2/query/video_generation/424010985738629",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
)
```

### 成功响应中的关键字段

```json
{
  "task": {
    "id": "424010985738629",
    "status": "succeeded",
    "content": {"url": "https://xxx/output.mp4"},
    "resolution": "2K",
    "duration": 5,
    "ratio": "9:16",
    "task_type": "generation",
    "usage": {
      "total_seconds": 5,
      "output_seconds": 5
    }
  }
}
```

## 与 `/minimax-storyboard` 的映射

通常 `/minimax-storyboard` 阶段 F 生成的 SEG asset pack 已经决定好每个 SEG 使用哪种模式：

- 无参考图/视频/音频 → t2va
- 只有首帧 panel → i2va
- 有参考图/视频/音频 → r2va
- 先生成 768P 再升级 2K → regeneration

`/minimax-video-dispatch` 读取 asset pack 后，按模式自动选择接口和组装 content。
