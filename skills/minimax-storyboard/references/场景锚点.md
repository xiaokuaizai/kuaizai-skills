# 场景锚点生成与管理规范.md
## 一、总则
### 1.1 文件定位
本规范仅负责全项目的**空间结构锚定、场景生成流程、空间一致性管控**，不涉及美术风格定义。
所有场景生成的风格统一要求，需同步遵循独立文件风格规范，风格规范优先级高于本规范。

### 1.2 模式判定
生成前先根据剧情场景形态自动匹配运行模式，并在输出开头强制声明所选模式及判定理由。

- **模式A 连片封闭场景**：所有子场景同属一个连续封闭空间（如整套住宅、同一栋建筑、整艘船舱），子场景间有固定墙体与连通关系。
- **模式B 离散序列场景**：剧情跨多个相互独立的空间单元（如卧室→班车→机场→飞机的旅行线），各单元无物理连通，仅按剧情顺序依次出现。

**判定原则**：
- 若人物需要在不同地点之间借助交通工具、出入口、通道进行空间切换，则这些空间属于模式B下的不同单元。
- 若人物在同一栋建筑/同一载具/同一连续空间内移动，不经过室外或独立建筑切换，则倾向于模式A。

### 1.3 内容边界
场景锚点仅负责描述空间结构、边界、光源、视觉锚点、相邻关系与生成依赖，不得包含具体分镜机位、人物走位、画面构图、镜头运动等分镜设计阶段内容。这些信息应在分镜设计（Shot List）阶段处理。

## 二、空间锚点体系
### 2.1 模式A（连片封闭场景）：单级全局锚点
- **锚点类型**：全局户型图（唯一空间基准，强制生成，不可省略）
- **核心作用**：锚定整套连续空间的整体结构，标注所有子场景名称、墙体走向、门洞朝向、连通路径、方位坐标系。该图是模式A下所有子场景生成的共同空间基准。
- **画面规格**：
  - 比例：16:9
  - 形式：线稿/平面图，浅色背景，深色墙体/区域边界线条
  - 标注：用简短中文在对应区域内或旁边标注子场景名称（如“客厅”“主卧”“厨房”）
  - 方位：建议添加简单“北↑”箭头或文字方位说明
  - 禁区：不得出现光影渲染、材质纹理、家具细节、人物、复杂编号或尺寸标注
  - 风格说明：本图不承载最终美术风格，仅作为空间结构参考
- **生成顺序**：必须先完成全局户型图线稿，再按“边缘→相邻→连通”顺序生成各子场景的 9:16 渲染图。
- **调用规则**：该空间内所有子场景生成时，必须带入全局户型图作为必带参考图，同时配套文字空间描述作为辅助。

### 2.2 模式B（离散序列场景）：单元独立锚点
- 取消全局场景序列总览图，各场景单元独立生成专属空间锚点，互不隶属、互不引用。
- **锚点类型**：场景单元布局图（每个单元一张，等效于该单元的「专属户型图」）
- **核心作用**：针对单个独立场景单元（如机场航站楼、民航客机），标注单元内所有人物活动子区的名称、区域边界、动线走向、出入口位置、关键道具点位，是该单元内所有子区域、分镜的直接空间基准。
- **画面规格**：
  - 比例：16:9
  - 形式：线稿/平面图，浅色背景，深色区域边界线条
  - 标注：用简短中文在对应区域内或旁边标注子活动区名称（如“值机区”“安检口”“候机厅”）
  - 动线：建议用虚线或箭头标出主要动线方向
  - 禁区：不得出现光影渲染、材质纹理、人物、复杂编号或尺寸标注
  - 风格说明：本图不承载最终美术风格，仅作为单元内部空间结构参考
- **生成时机**：按剧情出场顺序，逐个生成对应单元的布局图线稿；生成该单元内的子区域前，必须先完成本单元布局图。
- **调用规则**：单元内所有子活动区生成时，必须带入本单元布局图作为必带参考图，同时配套文字空间描述作为辅助。

#### 独立物理单元判定标准
满足以下任一条件，必须拆分为独立单元，**不得作为同一单元内的子活动区**：
1. 需要借助交通工具切换（如飞机、班车、电车、轮船、缆车）。
2. 需要经过出入口/通道离开一个空间后才能进入另一个空间（如走出机舱进入到达大厅、走出车厢进入街道、走出房门进入独立建筑）。
3. 属于不同建筑、不同地点或不同自然区域（如住宅与机场、森林与海岸、山洞与树下广场）。
4. 存在明显的时间或空间断裂提示（如“转场后”“第二天”“抵达后”“下车后”）。

**子活动区仅限同一单元内部**：同一单元内的子活动区必须位于同一连续物理空间内，人物可在不借助交通工具、不离开本单元的前提下到达（如机场大厅内的值机区、安检口、候机厅；住宅内的客厅、厨房、卧室）。

### 2.3 锚点图文件存储与文字描述规范

#### 2.3.1 文件存储位置

所有场景锚点图及其文字描述统一存放在任务目录的 `scenes/` 文件夹下，图与描述文件同名同目录，便于一一对应：

```text
项目任务目录/
├── scenes/
│   ├── global_floor_plan.png            # 模式A：全局户型图
│   ├── global_floor_plan.md             # 对应的文字空间描述
│   ├── unit_001_airport_layout.png      # 模式B：场景单元布局图
│   ├── unit_001_airport_layout.md       # 对应的文字空间描述
│   ├── scene_001_living_room.png        # 模式A子场景渲染图
│   ├── scene_002_kitchen.png
│   ├── unit_001_area_checkin.png        # 模式B子活动区渲染图
│   └── unit_001_area_security.png
```

#### 2.3.2 文字描述文件格式

每张 A/B 线稿布局图必须同步生成同名 `.md` 描述文件，作为图的补充说明和后续子场景生成的文字依据。文件内容格式：

```markdown
---
anchor_type: global_floor_plan            # 可选值：global_floor_plan / scene_unit_layout
mode: A                                   # A 或 B
unit_id:                                  # 模式B填写，如 unit_001
image_file: global_floor_plan.png
aspect_ratio: "16:9"
style_note: "线稿平面图，无光影材质，仅用于空间结构参考"
---
```

## 三、场景生成顺序规则
### 3.1 模式A（连片封闭场景）

模式A 的生成分为两个阶段：

1. **第一阶段：生成全局户型图线稿**
   - 输出 16:9 全局户型图（`scenes/global_floor_plan.png`）及同名 `.md` 文字描述。
   - 该图通过 QA 前，不得进入子场景渲染图生成。

2. **第二阶段：生成子场景渲染图**
   - 遵循「由边缘到内部、先单点后连通」的优先级：
     1. 第一优先级：边缘场景，即处于空间边界、邻接场景最少的独立房间，仅依托全局户型图生成。
     2. 第二优先级：与已生成场景直接连通的相邻场景，每轮仅新增1个未生成邻接面，保证衔接可校验。
     3. 第三优先级：过道、走廊等公共连通类场景，需在至少1个连通的独立场景生成完成后再生成。
   - 所有子场景渲染图比例统一为 9:16，保存到 `scenes/` 目录。

### 3.2 模式B（离散序列场景）

模式B 的生成同样分为两个阶段：

1. **第一阶段：逐个生成场景单元布局图线稿**
   - 按剧情出场顺序，为每个独立单元生成 16:9 场景单元布局图（`scenes/unit_XXX_layout.png`）及同名 `.md` 文字描述。
   - 本单元布局图通过 QA 前，不得生成该单元内的子活动区渲染图。

2. **第二阶段：单元内由总到分生成子活动区渲染图**
   - 单个单元内部，遵循「边缘→相邻→连通」的规则，依次生成单元内的所有子活动区画面。
   - 所有子活动区渲染图比例统一为 9:16，保存到 `scenes/` 目录。

3. 跨单元生成时，仅继承全局风格规范，不携带上一单元的空间锚点与成品图。

### 3.3 场景风格连续性检查
生成执行顺序表后，必须按剧情出场顺序核对相邻场景的风格适配条目（详见 `references/全局风格.md` 第五章「风格适配边界与冲突防控规则」）。若相邻两场在「色调大类 + 明暗强度 + 色彩饱和度」三个维度中同时变化 ≥2 个，且未提供合理过渡理由，必须暂停并调整风格适配方案或插入过渡场景，再进入子场景/子活动区生成环节。

## 四、参考图调用规则
### 4.1 核心原则
生成下级画面时，必带直属空间锚点图；同级相邻画面按需补充；跨单元不带入其他单元内部素材；所有画面同步遵循全局风格规范。

### 4.2 分级调用细则
| 生成对象          | 必带图像参考       | 补充参考图         |
| ------------- | ------------ | ------------- |
| 模式A 子场景       | 全局户型图        | 已生成的相邻场景成品图   |
| 模式B 单元布局图     | 无（仅遵循全局风格规范） | 无             |
| 模式B 单元内首个子活动区 | 本单元布局图       | 无             |
| 模式B 单元内相邻子活动区 | 本单元布局图       | 所有已生成的相邻子区成品图 |

### 4.3 内容权限边界
- 已生成完成的场景/子区域：允许在当前视角中自然展示内部，布局与风格需与参考图保持一致。
- 未生成的场景/子区域：**严禁展示内部陈设与结构**，仅允许展示房门、入口立面、通道轮廓。

## 五、参考图用途声明规则

所有参考图调用都须先满足 `references/导演分镜连续制作行为规范.md` 2.4 节的「参考图调用通用声明要求」（说明参考图身份、调用目的、使用方式、不用于什么）。

当基于父级场景图/布局图生成子场景或子活动区（或同一场景的新机位图）时，在上述通用声明之外，提示词还必须显式声明以下 4 个要素，避免模型把参考图当背景直接套用或误作风格参考。

### 必须写清楚的 4 个要素

1. **参考图是什么**
   - 例：`参考图是机场航站楼的单元布局图`
   - 例：`参考图是已生成的客厅全景`

2. **本次要生成的是参考图里的哪个局部**
   - 例：`基于该参考图生成同一机场航站楼内部的值机区`
   - 例：`基于该参考图生成客厅内的厨房操作台近景`

3. **从参考图继承什么**
   - 当参考图为线稿布局图（全局户型图 / 场景单元布局图）时：仅继承空间结构、区域方位、连通关系、建筑尺度；不继承光影、材质、色彩或风格。
   - 当参考图为已生成的渲染场景图时：继承建筑风格、色调、光影方向、材质体系、空间尺度。
   - 例（布局图）：`继承参考图的空间分区、区域方位和连通路径`
   - 例（渲染图）：`保持与参考图一致的地面材质、墙面颜色、自然光方向`

4. **当前画面新增/聚焦什么**
   - 例：`在值机区添加值机柜台、排队线和指示牌`
   - 例：`展示厨房操作台细节，同时保持与客厅的空间连贯`

### 推荐句式

```text
Based on the reference image of [父级场景/布局名称], generate [子场景名称/功能区域] located inside this [父级场景]. The reference defines the overall style, scale, layout, and lighting and must be preserved. Current focus: [子区域的具体内容]. Do not change the architecture style, color scheme, lighting direction, or material system. Add [子区域特有元素].
```

### 禁止写法

- 只说 "refer to the image"，不说明参考图身份
- 把参考图当背景直接套用（"use as background"）
- 不说明当前生成的是参考图中的哪个局部
- 让模型直接裁切/放大参考图，而不是基于它生成新视角

## 六、提示词强制约束规则
每个场景的提示词必须包含「风格描述+空间定位+邻接约束+画面类型」四部分。
1. **风格描述**：直接写入项目全局风格中对应场景的具体风格描述（色调、光影、材质、氛围），不得引用《全局风格.md》等文件名或章节名。
2. **空间定位描述**：明确当前场景在对应锚点图中的位置，以及与相邻区域的相对方位。若参考图为线稿布局图，必须同时用文字描述空间关系，避免模型误读图中标注。
3. **邻接场景约束**：
   - 未生成的相邻区域：仅显示房门/入口立面，不得展示内部任何陈设与结构。
   - 已生成的相邻区域：可根据视角自然展示内部，布局、材质与参考图严格一致。
4. **画面类型约束**：完整单视角场景、沉浸式氛围、统一光影；禁止多格拆分、设定集格式、分镜排版。

---

## 七、一致性校验规则
1. **结构校验**：场景布局、出入口位置、区域边界与对应空间锚点图完全匹配。
2. **衔接校验**：与相邻场景的衔接处（地面、墙面、门洞/通道），透视、材质、光照统一。
3. **边界校验**：未生成区域未出现内部内容，仅保留入口立面。
4. **层级校验（模式B）**：子区域与所属单元布局图的方位、比例、空间逻辑无矛盾。

## 九、输出前自检清单
生成或修改场景锚点后，必须逐项自检，全部通过后方可进入下游分镜/画面生成环节。

1. **模式声明**：已在输出开头明确声明模式A或模式B，并给出判定理由。
2. **单元拆分（模式B）**：每个独立单元均满足“独立物理单元判定标准”，不存在把交通工具、独立建筑、不同地点错误合并为同一单元的情况。
