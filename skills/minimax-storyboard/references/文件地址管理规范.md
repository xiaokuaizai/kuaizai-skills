# 文件地址管理规范

> 本规范规定如何维护每个任务中的文件地址索引，确保 Agent 不会遗漏或记错图片、参考图、音频等文件的路径。
> 配套文件：`doc/文件地址管理.md`。

## 1. 文件位置

每个任务必须维护一份：

```text
<项目目录>/doc/文件地址管理.md
```

和所有文字产物一样，统一放在 `doc/` 目录下。

任务根目录下同时维护以下产物目录：

```text
<项目目录>/
├─ doc/                        # Markdown 文字产物与登记表
├─ panels/                     # 单镜头分镜图源图
├─ refs/                       # 参考图（角色 / 场景 / 道具 / 拼接）
├─ blocking/                   # 独立 SVG 站位图（按需；HTML 内嵌 SVG 强制）
├─ 故事板参考图/                # SEG 级故事板参考图（强制）
├─ scripts/                    # 任务级脚本
│  ├─ capture/                 # 截图、采集类脚本
│  ├─ upload/                  # 上传、同步类脚本
│  ├─ convert/                 # 格式转换、批量处理脚本
│  └─ qa/                      # 校验、检查类脚本
└─ *_director_full_table.html  # 导演总表
```

`scripts/` 用于存放**本任务运行过程中生成或定制的脚本**，不是 skill 自带的通用脚本。

---

## 2. 什么时候更新

**每生成一张图、每收到用户提供的文件、每输出一个非 Markdown 产物、每生成或更新一个任务级脚本，都必须立即追加记录。**

具体触发时机：

1. 生成单镜头分镜图后（`panels/SH-XX.png`）。
2. 生成角色三视图、服装衍生图、场景图、道具图后。
3. 生成 SVG 站位图、故事板参考图后。
4. 用户提供参考图、参考音频、参考视频后。
5. 运行 `scripts/combine_reference_sheets.py` 生成拼接参考图后。
6. 输出 HTML 总表、Markdown 总表和 SEG 故事板参考图后（强制登记）；PNG 长图生成后也要登记。
7. **生成或更新任务级脚本后（`scripts/xxx/xxx.py` 或 `scripts/xxx/xxx.ps1`）**。

---

## 3. 表格格式

```markdown
# 文件地址管理

## 登记规则

- 每生成一张图或收到用户提供的文件路径，立即追加一条记录。
- 路径优先使用相对项目根目录的相对路径，例如 `panels/SH-01.png`。
- 如果用户提供的是绝对路径，原样记录，并在备注里注明「用户提供」。
- 类型和用途必须写清楚，方便后面选参考图时快速筛选。

## 文件登记表

| 文件名 | 类型 | 用途 | 关联对象 | 路径 | 状态/备注 |
|---|---|---|---|---|---|
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 文件名 | 是 | 不带路径的文件名，例如 `SH-01.png`。 |
| 类型 | 是 | 分镜图 / 角色参考 / 场景参考 / 道具参考 / 站位图 / 拼接参考图 / 音频 / 脚本 / 其他。 |
| 用途 | 是 | 一句话说明这张文件在流程中的作用。 |
| 关联对象 | 是 | 关联的镜头号、SEG 号、角色名、场景名、道具名等。 |
| 路径 | 是 | 相对项目根目录的路径，或用户提供的绝对路径。 |
| 状态/备注 | 否 | 已生成 / 用户提供 / 待更新 / 已弃用，或其他补充信息。 |

---

## 4. 路径写法

优先使用**相对路径**，从项目根目录开始：

```text
panels/SH-01.png
refs/characters/女主_三视图.png
refs/scenes/客厅_全景.png
blocking/SEG-01_blocking.svg
scripts/capture/capture_seg01.py
scripts/upload/upload_panels_to_oss.py
```

如果用户提供的是绝对路径，例如 `G:\refs\male_lead.png`，原样记录：

```text
G:\refs\male_lead.png
```

## 6. 使用场景

- 写 `Minimax H3 Segments` 最终提示词前，先查 `doc/文件地址管理.md`，按 SEG 挑选需要的参考图。
- 生成 HTML 总表时，按 `路径` 列引用 `panels/` 下的单镜头图。
- 生成站位图或故事板参考图后，回填路径以便下游流程使用。
- 用户临时提供参考图时，立即登记，避免后续遗漏。
- **运行任务级脚本前，先查登记表确认脚本路径和用途，避免调用过期或被覆盖的脚本。**

---

## 7. 常用本地脚本说明

本 skill 自带两个本地文件管理脚本，与 `/minimax-story-package` 的上传/归档脚本职责不同，不要混用：

| 脚本 | 作用 | 与 minimax-story-package 的区别 |
|---|---|---|
| `scripts/register_output.py` | 把单个本地文件登记到 `doc/文件地址管理.md` | `minimax-story-package/scripts/register_outputs.py` 负责解析路径、上传 OSS、更新 manifest；`register_output.py` 只做本地 Markdown 登记 |
| `scripts/archive_output.py` | 把本地旧版本文件归档到原目录下的 `_archive` 文件夹 | `minimax-story-package/scripts/archive_local_version.py` 按 OSS 规范归档；`archive_output.py` 只做本地备份 |

使用时机：

- 生成本地文件（如 panel、站位图、故事板参考图）且尚未上传 OSS 时，可用 `register_output.py` 先登记。
- 覆盖已存在的本地文件前，可用 `archive_output.py` 归档旧版。
- 需要上传 OSS 时，统一调用 `/minimax-story-package/scripts/register_outputs.py`（带 `--upload`），上传后它会自动更新登记表和 manifest。

## 8. QA 检查项

- `doc/文件地址管理.md` 是否存在。
- `panels/` 下的图片是否已全部登记。
- 用户提供的参考图是否已登记。
- **`scripts/` 下的任务级脚本是否已登记。**
- 文件名、路径、关联对象是否写清楚。
- 已弃用的文件是否标注「已弃用」，避免误用。
