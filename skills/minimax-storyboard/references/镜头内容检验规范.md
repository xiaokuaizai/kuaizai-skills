# 镜头内容检验规范

> 本规范用于在生成 HTML 导演总表之前，反向校验每个镜头的分配时长是否足够装下它必须交代的内容。
> 配套使用：`output-format.md` 中的 `Shot List` 字段、`scripts/validate_storyboard.py` 时长校验。

## 1. 什么时候做

在 `Shot List` 已经列出、但还没有最终组合成 `Minimax H3 Segments` 之前做。

**顺序**：
1. 设计镜头 → 2. 填写 `Shot List` → **3. 生成本检验文件** → 4. 调整镜头时长或拆分 SEG → 5. 最终 SEG 分段。

---

## 2. 输出文件

每个任务输出一份：

```text
<任务目录>/doc/镜头内容检验.md
```

Agent 必须单独生成这份文件，不要把它和 `Shot List` 或 `Minimax H3 Segments` 混在一起写。

---

## 3. 核心原则

- **内容决定时长**：一个镜头需要多少时间，由「观众必须看到/听到/理解的信息量」决定，而不是由 Agent 凭感觉拍脑袋。
- **低估比高估更危险**：时长少了，Minimax H3 会来不及交代信息；时长多了，可以删减或放慢。
- **先拆镜头，再压时长**：如果一个镜头要交代的太多，优先拆成两个镜头，而不是把每个信息都压到 0.5 秒。

---

## 4. 内容类型与最低时长

把每个镜头必须出现的内容拆成以下几类，分别估算：

| 内容类型 | 说明 | 最低时长 |
|---------|------|---------:|
| 场景/人物识别 | 观众需要时间认出这是哪里、谁在画面里 | 1.5 秒 |
| 动作完成 | 推门、转身、坐下、拿起手机等完整动作 | 2.0 秒 |
| 情绪读取 | 表情变化、反应、停顿被观众感知 | 1.0 秒 |
| 道具/细节揭示 | 关键道具、屏幕、文字、证据被注意到 | 1.0 秒 |
| 台词/旁白 | 实际说出的对白或旁白 | 按字数计算 |
| 反应/留白 | 说完话后给观众的反应时间或转场余量 | 0.5 秒 |

### 4.1 台词时长计算

不调用 TTS，按字数估算：

- **正常语速**：4 字/秒。
- **情绪激动、信息密集、需要强调**：3 字/秒。

例如：

| 台词 | 语速 | 字数 | 估算时长 |
|-----|------|-----:|---------:|
| 「你怎么来了？」 | 正常 | 6 | 6 ÷ 4 = 1.5 秒 |
| 「我告诉你，这件事没完！」 | 情绪激动 | 10 | 10 ÷ 3 ≈ 3.3 秒 |

### 4.2 多内容叠加

如果同一镜头里多个内容同时发生，**不要简单相加**，取主导项即可：

- 推门（2.0 秒） + 惊讶表情（1.0 秒） → 主导是动作 2.0 秒，表情可在动作中段被读出。
- 说话（3.0 秒） + 转身（2.0 秒） → 取最长 3.0 秒，但转身必须在 3 秒内完成，否则要延长或拆分。

如果内容之间是** sequential（先后发生）**，则相加：

- 识别场景（1.5 秒） → 推门（2.0 秒） → 惊讶表情（1.0 秒） → 反应留白（0.5 秒） = **5.0 秒**

---

## 5. 输出表格格式

每个镜头一行小计，下面列出所有内容项：

```markdown
## Shot 内容检验

| 镜头 | 必须出现的内容 | 类型 | 估算秒数 | 是否与当前分配冲突 |
|------|---------------|------|---------:|:----------------:|
| SH-01 | 女主站在门口，门外光线涌入 | 场景识别 | 1.5 | |
| SH-01 | 女主推门进入 | 动作完成 | 2.0 | |
| SH-01 | 女主惊讶表情 | 情绪读取 | 1.0 | |
| SH-01 | 「你怎么来了？」 | 台词（4字/秒） | 1.5 | |
| SH-01 | 说完后的反应留白 | 反应/留白 | 0.5 | |
| **SH-01 小计** | | | **6.5** | **当前分配 4.0s ❌ 不足，建议 ≥ 6.5s** |
| SH-02 | 男主坐在沙发上抬头 | 动作完成 | 1.5 | |
| SH-02 | 男主皱眉、眼神冷 | 情绪读取 | 1.0 | |
| **SH-02 小计** | | | **2.5** | **当前分配 3.0s ✅ 足够** |
```

---

## 6. 冲突处理规则

当 `最低时长 > 当前分配时长` 时，按以下优先级处理：

1. **优先拆分镜头**：把 sequential 的内容拆成两个镜头。
2. **其次延长镜头**：如果内容无法拆分，延长当前镜头时长。
3. **最后压缩内容**：只有当情绪/表演允许快速带过，才减少某个内容项的时长，并在备注中说明。

---

## 7. SEG 总时长约束

调整完单个镜头后，再检查 SEG：

- **硬上限**：15 秒。
- **目标区间**：8-13 秒，优先把 SEG 控制在这个区间。
- **例外**：连续表演、慢揭示或长镜头可申请 12-15 秒，但必须在 `doc/视频分段.md` 中注明理由。
- 如果一个 SEG 内的镜头最低时长加起来超过 13 秒，优先拆 SEG，而不是压缩单个镜头。

---

## 8. 台词/旁白文本完整性校验

当镜头或 SEG 包含对白、旁白、画外音或内心独白时，必须额外校验：

### 8.1 原文完整性

- 从所有 SEG 的提示词时间轴中提取正式文本，按出现顺序拼接。
- 拼接结果必须与源剧本中的原始文本**完全一致**，不得增、删、改任何一个字。
- 如果原始文本已做语义拆分，拆分后的所有片段拼接起来也必须等于原始文本。

### 8.2 语义断点检查

- 每个拆分点必须落在句子结尾、完整从句结尾、说话人回合切换、情绪转折或自然停顿处。
- **禁止**从以下位置切断：名词短语中间、动词短语中间、完整从句中间、引号内一句话中间、数字/时间/专有名词中间。
- 所有拆分点必须在 `doc/文本语义拆分表.md` 中记录拆分理由。

### 8.3 时长与语义冲突处理

- 先保证语义完整和原文不变，再校验时长。
- 若语义完整拆分后某片段仍导致 SEG 超过 13 秒，优先继续细分语义单元，而不是压缩文本、删字或加速。
- 若无法继续拆分且确需保留长文本，按 7.1 例外流程处理。

---

## 9. 与 validate_storyboard.py 的配合

`scripts/validate_storyboard.py` 会读取 `Shot List`、`镜头内容检验.md` 和 `文本语义拆分表.md`：

- 检查每个镜头是否有 `required_content`。
- 如果 `min_duration` 缺失，脚本会根据 `required_content` 自动估算并提示。
- 检查 `duration >= min_duration`。
- 检查每个 SEG 总时长 `<= 15s`，并提示 8-13 秒目标区间偏离。
- 检查 `doc/文本语义拆分表.md` 中的原文拼接完整性。
- 检查是否存在句中切断等非法语义断点。

未通过校验前，禁止进入 HTML 总表制作。
