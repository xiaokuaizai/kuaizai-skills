# 人物锚点与三视图资产管理规范（Skill）

> 本规范为**强制调用类Skill**，所有涉及人物角色的视频脚本、分镜、AI生成资产制作任务，只要符合触发条件必须完整执行，不得跳过任何核心步骤。

## 1. 触发条件

满足以下任一条件时，本规范自动强制启用：

1. 经剧本/脚本分析，确认剧中存在人物角色，且人物满足「多次出场、拥有台词、存在特写镜头」任一属性
2. 剧情中人物出现服装、造型变更，需要保障多镜头人物形象一致性
3. 项目需要沉淀可复用的人物资产，跨支线/跨主线共用同一人物形象

> 仅单次出场、无台词、无特写的背景路人角色，可不纳入锚点管理范围。

## 2. 核心职责

1. 解析剧本内容，提取全量人物信息，梳理出场频次、台词节点、服装变化节点
2. 向用户确认「人物锚点」资产根目录路径；实体文件固定存放于 `人物锚点/实体/` 下，不由用户单独指定
3. 比对现有资产库，校验人物基础三视图、对应剧情服装三视图是否存在
4. 基础资产缺失时，生成人物标准三视图作为锚点基准；服装变更时，**必须基于原有基础三视图衍生新版服装三视图**，不得独立重绘人物
5. 按统一目录结构归档所有资产，在根目录维护总资产说明文档，记录人物来源、剧情来源、服装说明等信息
6. 作为后续所有镜头画面生成的人物一致性依据，保障多镜头、多支线人物形象统一

## 3. 目录结构规范

所有资产统一收纳在「人物锚点」根目录下，**资产说明.md放置于根目录，作为全项目唯一总台账**；资产按「基础基准-支线/主线衍生」二级分类管理，各服装子文件夹内不再单独放置说明文件。

```text
人物锚点/
├─ 资产说明.md              # 根目录总说明，统一登记所有人物资产与溯源信息
├─ 实体/                    # 人物解析实体文件，按固定格式记录每个人物的设定与分析
│  ├─ 人物A.md
│  └─ 人物B.md
├─ 人物三视图/              # 基础基准库，全项目通用，存放所有人物的标准三视图
│  ├─ 人物A_基础三视图.png
│  └─ 人物B_基础三视图.png
└─ 人物服装三视图/          # 衍生服装库，按支线/主线分文件夹管理
   ├─ 支线1_人物服装三视图/
   │  └─ 人物A_造型1三视图.png
   ├─ 支线2_人物服装三视图/
   │  └─ 人物A_造型2三视图.png
   └─ 主线1_人物服装三视图/
      └─ 人物B_造型1三视图.png
```

- **实体**为人物解析文件，固定存放于 `人物锚点/实体/` 目录下，每人一个 `.md` 文件，按统一格式编写
- **人物三视图**为唯一基准源，同一人物仅保留一份基础版本，跨所有支线/主线通用
- 服装衍生版本按「支线/主线编号+人物服装三视图」命名文件夹，互不干扰
- 所有资产的来源、说明、版本信息统一汇总至根目录 `资产说明.md`

## 4. 实体文件格式规范

`人物锚点/实体/<人物名>.md` 为单个人物的解析与设定文件，用于沉淀人物设定、性格、弧线与关联关系。实体文件固定存放于 `人物锚点/实体/` 目录下，每人一个 `.md` 文件，必须采用以下结构和 frontmatter。

### Frontmatter

```yaml
---
title: 人物名
created: YYYY-MM-DD
updated: YYYY-MM-DD
source_count: 出场次数
aliases: [别名1, 别名2]
tags: [实体, 人物, 主角/配角]
---
```

### 必填章节

1. **基本信息**
   - 姓名、性别、年龄、身高、体型、身份、所属组织/学校等
2. **性格特质**
   - 核心性格标签与具体表现
3. **标志性细节**
   - 道具、配饰、穿着风格、表情特征、习惯性动作
4. **人物弧线**
   - 从起点到终点的关键转变节点
5. **关键能力**
   - 对剧情有推动作用的能力或技能
6. **关键关系**
   - 与其他人物、组织、地点的关系
7. **出场章节**
   - 该人物出现的章节/场次列表
8. **关联页面**
   - 相关人物、项目、地点的链接或引用

## 5. 标准执行流程（强制步骤）

### 步骤1：剧本人物分析识别

1. 通读完整剧本/支线脚本，提取所有出场人物清单
2. 为每个人物标注：出场次数、是否有台词、是否存在服装/造型变化、是否有正面特写
3. 筛选出核心人物（多次出场/有台词/有特写），纳入锚点管理流程；路人背景角色标记为无需锚点

### 步骤2：资产路径确认

向用户确认项目内「人物锚点」资产根目录的完整路径。实体文件固定存放于 `人物锚点/实体/` 下，不单独向用户询问存放位置。未获得根目录确认前，不得擅自创建目录、生成资产。

### 步骤3：现有资产比对校验

进入人物锚点根目录，对每位核心人物逐一核对：

1. 「人物三视图」目录下，是否存在该人物的基础标准三视图
2. 对应支线/主线的服装子目录下，是否存在该人物对应剧情造型的服装三视图
3. `实体/` 目录下，是否存在该人物的实体文件 `<人物名>.md`，且内容符合第 4 节格式规范
4. 登记比对结果：已存在且符合设定的标记为「可复用」；缺失或不符合的标记为「待生成」
5. 所有比对结果同步更新至根目录 `资产说明.md`

### 步骤4：基础三视图生成（缺失时执行）

1. 无对应基础三视图的人物，基于剧本人物设定生成标准正、侧、背一致的三视图
2. 生成后归入「人物三视图」目录，作为该人物所有服装版本的唯一基准锚点
3. 同步更新 `实体/<人物名>.md` 人物实体文件，按第 4 节格式补充人物来源、设定依据、基础资产路径、人物弧线、关键关系等内容
4. 在根目录 `资产说明.md` 中新增该人物的基础资产登记

### 步骤5：服装变更衍生处理

1. 当剧情中人物服装发生变化时，**必须以该人物的基础三视图为锚点**，衍生生成对应服装造型的新版三视图，禁止脱离基准独立重绘
2. 新版三视图归入对应支线/主线的「人物服装三视图」子文件夹
3. 在根目录 `资产说明.md` 中追加该服装版本的完整记录，包含人物、所属支线、造型说明、文件路径、来源溯源

## 6. 根目录资产说明文档规范

`人物锚点/资产说明.md` 为全项目人物资产总台账，必填内容结构如下：

```markdown
# 人物锚点资产总说明

## 一、人物实体文件清单
| 人物名称 | 实体文件路径 | 创建时间 | 更新时间 | 状态 |
|---------|-------------|---------|---------|------|
| 人物A   | ./实体/人物A.md | 202X-XX-XX | 202X-XX-XX | 已完善/待补充 |

## 二、基础人物三视图清单
| 人物名称 | 人物形象来源 | 基础资产路径 | 版本号 | 生成时间 |
|---------|-------------|-------------|-------|---------|
| 人物A   | 剧本设定/参考图 | ./人物三视图/人物A_基础三视图.png | v1.0 | 202X-XX-XX |

## 三、衍生服装三视图清单
| 人物名称 | 所属支线/主线 | 服装造型说明 | 资产文件路径 | 剧情来源 | 版本号 | 生成时间 |
|---------|-------------|-------------|-------------|---------|-------|---------|
| 人物A   | 支线1       | 日常居家造型 | ./人物服装三视图/支线1_人物服装三视图/人物A_造型1三视图.png | 第X段剧情 | v1.0 | 202X-XX-XX |
```

## 7. 强制约束与优先级

1. **优先级规则**：人物锚点资产确认 > 分镜画面生成 > 道具场景设计。未完成人物锚点校验与资产准备，不得进入单镜头画面生成环节。
2. **一致性约束**：同一人物的所有服装版本三视图，必须基于同一份基础三视图衍生，五官、身材比例、特征标识必须完全统一。
3. **复用规则**：已存在的人物基础三视图全项目通用，不得为不同支线重复生成不同版本的基础人物形象。
4. **溯源规则**：所有人物资产必须在根目录 `资产说明.md` 中可追溯，无登记记录的资产视为无效资产。
5. **实体文件规则**：每位核心人物必须存在 `实体/<人物名>.md` 文件，且内容符合第 4 节格式规范；实体文件缺失或不完善时，不得进入三视图生成或单镜头画面生成环节。

## 8. 三视图固定提示词

布局强制段（紧跟人物描述后）

```text
Left half: character upper-body close-up; right half: same character in front, side, back full-body three views. Consistent features, clothing details and proportions across all views, pure white background
```

末尾固定质量约束

```text
4K ultra HD, clean and noise-free, crisp complete details, balanced colors, stable composition, smooth edges without distortion, natural texture, pure flawless image quality
```

### 风格约束

所有人物三视图生成提示词必须包含项目统一风格描述。风格以 `references/全局风格.md` 中定义的「全局核心风格基准」为最高优先级：

- 若 `references/全局风格.md` 已定义全局核心风格，优先使用该风格描述。
- 若未单独定义或需要默认值，使用：

```text
AI风格化3D动画
```

风格描述应放在人物主体描述之后、布局强制段之前，确保生成的人物资产与项目最终视频风格一致。当全局风格与单条提示词中的风格描述冲突时，以全局风格为准。

## 9. 服装衍生图生成提示词规则

为角色生成服装变更/衍生三视图时，提示词必须明确写出参考图的作用，并且清楚表达本次生成的本质是「为同一角色更换服装」，而非重绘新人物。

### 必须包含的说明

1. **参考图作用声明**：
   - 明确说明参考图用于锁定人物五官、体型、姿态、特征标识，保持不变
   - 明确说明本次仅变更服装/造型，人物本身不变

2. **换衣本质声明**：
   - 在 prompt 中明确写出 `same character, only outfit changed`、`keep face, body, and proportions identical to reference, change clothing to ...` 或等价中文表达
   - 禁止出现可能让模型理解为「生成另一个相似人物」或「生成时尚模特」的表述

3. **参考图权重与位置**：
   - 人物基础三视图作为高权重参考图优先输入
   - 在 prompt 开头或人物描述之后立即声明参考图用途，避免模型忽略

4. **风格一致性声明**：
   - 提示词必须包含项目统一风格，优先使用 `references/全局风格.md` 中定义的「全局核心风格基准」
   - 若全局风格未定义具体描述，默认使用 `AI风格化3D动画`
   - 确保衍生服装图与基础三视图、项目最终视频风格保持一致；冲突时以全局风格为准

### 推荐提示词结构

```text
Generate a character three-view reference sheet based on the provided reference image. The reference image defines the character's face, body proportions, hairstyle, and identifying features and must be preserved exactly. This is the SAME character with ONLY the outfit changed. Style: [引用 references/全局风格.md 的全局核心风格基准，未定义时填写 AI风格化3D动画]. New outfit: [详细服装描述]. Left half: character upper-body close-up; right half: same character in front, side, back full-body three views. Consistent features, clothing details and proportions across all views, pure white background. 4K ultra HD, clean and noise-free, crisp complete details, balanced colors, stable composition, smooth edges without distortion, natural texture, pure flawless image quality.
```

### 禁止写法

- 不声明参考图用途，直接描述服装
- 使用 `fashion design sheet`、`different models wearing...`、`various characters in...` 等弱化角色同一性的表述
- 只写服装描述而不绑定到具体人物，导致模型生成陌生面孔或不同体型
